# แนวทางดำเนินกิจกรรม

## เตรียมก่อนสอน

- ลองทำทุกบทใน Repository ฝึกที่ไม่มีข้อมูลจริง โดยเฉพาะ Conflict และ Revert
- ตรวจเวอร์ชันระบบกับ GitHub Desktop และเตรียมเส้นทางเว็บสำหรับเครื่องที่ไม่รองรับ
- เตรียมบัญชี/เครื่องสำหรับสาธิต ไม่ใช้ Repository ที่มีงานสำคัญ
- ให้ผู้เรียนเข้าสู่ระบบและตรวจอีเมลก่อนเริ่มกิจกรรม
- จัดคู่ A/B สำหรับ Review ตรวจว่ารับคำเชิญ Collaborator แล้วก่อนบท 06
- กำหนดวิธีส่งงานและสิทธิ์เข้าถึง Repository Private ให้ชัดเจน

## วิธีสอนแต่ละบท

เริ่มจากโจทย์ให้เห็นเหตุผล สาธิตงานสั้นหนึ่งรอบ แล้วให้ผู้เรียนทำเอง ระหว่างเดินตรวจให้ถาม “ตอนนี้อยู่ Repository และ Branch ไหน” และ “การเปลี่ยนแปลงนี้อยู่บนเครื่องหรือบน GitHub” ไม่ควรคลิกแก้ให้ทันทีโดยผู้เรียนไม่อธิบาย

ใช้ Checkpoint เป็นเงื่อนไขไปบทถัดไป ให้ผู้ที่เสร็จก่อนทำ Mini Challenge และช่วยอธิบายแก่เพื่อนโดยไม่ทำแทน

| บท | จุดสาธิตสำคัญ | ข้อผิดพลาดที่ควรเฝ้าดู |
|---|---|---|
| 01 | เปิด Commit และ Diff | เข้าใจว่า Git กับ GitHub คือสิ่งเดียวกัน |
| 02 | Owner/Visibility/README | สร้างผิดบัญชีหรือใส่ข้อมูลส่วนตัว |
| 03 | Preview และ Diff | Commit message ไม่สื่อความหมาย ลิงก์ผิดระดับโฟลเดอร์ |
| 04 | หยุดให้เห็นหลัง Commit ก่อน Push | แก้ไฟล์นอกโฟลเดอร์ Clone หรือคิดว่า Save ส่งงานแล้ว |
| 05 | สลับ Branch หลัง Commit | สร้าง Branch จากฐานผิดหรือมีงานค้าง |
| 06 | Base/Compare และ Files changed | Review PR ตนเอง หรือ Merge ก่อนเพื่อนตรวจ |
| 07 | สอง Branch จากฐานเดียวกัน | สร้าง title-b หลัง Merge title-a ทำให้ไม่เกิด Conflict |
| 08 | Acceptance criteria และ Closes | ใช้เลข Issue ผิดหรือใส่ keyword ใน Comment แทน description |

## ตรวจลำดับบท 07 ก่อนสอน

ต้องสร้าง title-a และ title-b จาก Commit ฐานเดียวกัน **ก่อน Merge Branch ใดเข้า main** แล้วค่อย Merge title-a เมื่อ main เปลี่ยนแล้ว title-b จึงชนกับบรรทัดเดียวกัน ใช้ไฟล์เล็กที่กำหนดไว้ หลีกเลี่ยงให้คู่ฝึกแก้ main ระหว่างสาธิต

Revert ใช้ Commit ธรรมดาที่เพิ่งเพิ่ม Temporary note ใน Branch แยก ไม่ใช้ Commit Merge ที่มีงานเพื่อนรวมอยู่ กิจกรรมนี้ตรวจจากประวัติ Branch ทดลอง ไม่บังคับเปิด PR ที่ไม่มีผลสุทธิ

## ปรับระดับผู้เรียน

ผู้เริ่มต้นมากให้ทำบท 01–03 บนเว็บก่อนและทบทวน Save/Commit/Push แล้วค่อยเริ่ม Desktop ผู้ที่พร้อมแล้วทำเส้นทางเต็ม ผู้ใช้เว็บอย่างเดียวให้ระบุ Desktop/Revert ว่าเป็นการดู Demo ตามจริง การเรียนรู้บนเว็บยังประเมิน Branch/PR/Review/Issue ได้

Fork เป็นทางเลือกเสริมเมื่อไม่ให้สิทธิ์ Collaborator ไม่จำเป็นต้องสอนทั้งสองรูปแบบพร้อมกันตั้งแต่ต้น

## ปิดกิจกรรม

ให้ผู้เรียนเปิด Repository อธิบายหนึ่ง Commit หนึ่ง Review และหนึ่งปัญหาที่แก้เอง ตรวจงานตาม [เกณฑ์](assessment.md) และให้คำแนะนำจากหลักฐานจริง แนะนำให้ทบทวนสิทธิ์ Collaborator หลังเรียนตามความจำเป็นของทีม
