# บท 01 · เข้าใจ Git และ GitHub

## เป้าหมาย

แยกบทบาทของ Git, GitHub และ GitHub Desktop ได้ และอ่าน Repository กับประวัติการเปลี่ยนแปลงเบื้องต้นได้

## สถานการณ์

ไฟล์ `report-final.md`, `report-final-new.md` และ `report-final-new2.md` ทำให้ไม่รู้ว่าอะไรเปลี่ยนและฉบับไหนถูกต้อง เราจะใช้ไฟล์ชื่อเดิมแล้วเก็บประวัติเป็น Commits

## แนวคิดที่ต้องใช้

| คำ | ความหมาย | ตัวอย่างในกิจกรรม |
|---|---|---|
| Git | เครื่องมือจัดการเวอร์ชัน ทำงานบนเครื่องได้ | เก็บประวัติไฟล์โดยไม่ต้องออนไลน์ตลอดเวลา |
| GitHub | บริการเก็บ Git Repository และทำงานร่วมกัน | เปิด PR และ Review ผ่านเว็บ |
| GitHub Desktop | โปรแกรมหน้าต่างสำหรับทำงานกับ Git | Commit และ Push โดยไม่พิมพ์คำสั่ง |
| Repository | โปรเจกต์ที่มีไฟล์และประวัติ | `my-first-project` |
| Commit | จุดบันทึกการเปลี่ยนแปลงที่เลือก พร้อมข้อความและรหัส | `docs: add skills section` |
| Branch | เส้นทางการพัฒนาที่ชี้ไปยังชุดประวัติ | `main` และ `add-project-page` |
| Local/Remote | สำเนาบนเครื่อง/Repository อีกแห่งที่ติดต่อกัน | เครื่องผู้เรียน/GitHub |

Save ในโปรแกรมแก้ไขเปลี่ยนไฟล์ แต่ยังไม่สร้าง Commit และ Commit บนเครื่องยังไม่ส่งขึ้น GitHub จนกว่าจะ Push ส่วน Commit ที่ทำบนเว็บไซต์จะอยู่บน GitHub ทันที

## Demo โดยผู้สอน

เปิด Repository หลักสูตร ชี้ตำแหน่งชื่อเจ้าของ ชื่อ Repository, Branch และ README จากนั้นเปิด Commits แล้วเลือก Commit ที่แก้ข้อความหนึ่งรายการให้ดู Diff

## ลงมือทำ

1. เปิด [Repository หลักสูตร](https://github.com/drsanti/github-hands-on)
2. ดูชื่อ `drsanti/github-hands-on` แยกว่าใครเป็นเจ้าของและอะไรคือชื่อโปรเจกต์
3. เปิด `README.md` แล้วกลับหน้า Code สังเกต Branch ที่เลือกอยู่
4. เปิดลิงก์ Commits ใกล้รายการไฟล์ แล้วเลือก Commit ที่มีการแก้ README
5. อ่านข้อความ Commit และดูบรรทัดที่เพิ่ม/ลบใน Diff สีเขียวมักแสดงบรรทัดเพิ่ม สีแดงแสดงบรรทัดลบ อ่านเครื่องหมาย `+`/`-` ประกอบด้วย
6. จดลิงก์ Commit และสรุปหนึ่งประโยคว่าการเปลี่ยนแปลงนั้นทำอะไร ไม่ต้องแก้ไฟล์หลักสูตร

## Checkpoint

- [ ] ชี้ตำแหน่งเจ้าของ Repository และ Branch ได้
- [ ] เปิด Commit หนึ่งรายการและอธิบาย Diff ได้
- [ ] อธิบายว่า Save, Commit และ Push ต่างกันอย่างไร

## Mini Challenge

เลือกอีกหนึ่ง Commit แล้วให้เพื่อนเดาว่ามีอะไรเปลี่ยนจาก Commit message ก่อนเปิดดู Diff เปรียบเทียบว่าข้อความชัดเพียงใด

## คำถามทบทวน

1. ไม่มีอินเทอร์เน็ตยัง Commit บนเครื่องได้หรือไม่ เพราะอะไร?
2. GitHub Desktop กับ GitHub website ทำหน้าที่เหมือนกันทั้งหมดหรือไม่?
3. เหตุใดจึงไม่ควรเก็บทุกเวอร์ชันเป็นไฟล์ชื่อใหม่?
